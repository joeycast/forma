## Finding I1: confirmed cross-tab storage loss, transactional replacement

An earlier browser journey reported both duplicate operations successful but showed only one copy after refresh. Initial focused reruns passed, so root retained the investigation and added a substrate stress test. A subsequent run reproduced the actual flaw: 100 read/modify/write operations under the same exclusive Web Lock produced duplicate counts at 50/51 and only 98 retained entries. Locks alone did not ensure coherent localStorage snapshots across browser renderers. The old helper and its misleading shared-memory tests have been removed.

Browser library and design-system snapshots now use the `forma-workspace-v1` IndexedDB database and one `snapshots` object store. The shared helper executes read, validation/update and write in one readwrite transaction, and reports success only after transaction completion. Every subsequent read uses the authoritative database. Initial migration is transactional, reads existing localStorage keys only when no database snapshot exists, and leaves their original bytes untouched. There is no dual-write mirror. Missing storage, unsupported/corrupt snapshots, quota errors and aborted writes fail closed; async metadata refreshes ignore older requests.

Browser qualification passed for concurrent UI writes, quota/abort preservation, migration and the exact helper's 100-write stress with both writer tabs and a fresh third reader. The captured pre-fix failure is retained at `/workspace/forma-review/verification/confirmed-browser-storage-loss/`.
