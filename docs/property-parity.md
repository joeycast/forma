# Editor property parity (v2)

This matrix compares the native v2 document fields in `schema/forma.v2.schema.json` with the current editor UI. “Advanced” means the raw document/design-system JSON editor; “derived” means the engine or renderer supplies the value; “read-only” means shown as effective output without a general-purpose edit control.

## Current boundary

The native schema accepts more style keys on each element than the renderer meaningfully consumes. The editor intentionally gates normal controls and design-system defaults through `STYLE_CAPABILITIES`; unsupported combinations are omitted rather than presented as effective. Full JSON editing/import remains available for schema-valid forward-compatible snapshots. Shape options come from `SHAPE_NAMES`; node `aspectRatio` is an editable capability. Edge label typography is not currently a capability, and group typography is limited to `fontFamily` until the renderer provides meaningful support.

The schema permits `style.secondary` on edges/groups, but the capability registry currently marks secondary paint node-only. Those values can round-trip through schema JSON but are not exposed as active edge/group controls. Design-system advanced JSON is the fallback for schema-valid fields outside the supported capability surface.
