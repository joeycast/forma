# Layout performance verification

This report records the final serial Node benchmark for the F6 layout and inspection path. Each size ran in its own process with a 65-second hard timeout; no other tests or browser traces were active. The fixture is a deterministic layered RIGHT graph with forward-only edges, default node text, and one explicitly styled rectangular node so the same 20-node document can exercise a warm cosmetic edit without changing its resolved variant. Node and edge counts, layout/ELK/non-ELK time, cold inspection time, and diagnostic counts were captured for every case.

| Nodes / edges | Cold layout | ELK | Routing and other layout | Inspection | Worker compute* | Errors | Warnings | Crossings | Routing fallbacks | Retained |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| 20 / 54 | 3.926 s | 2.575 s | 1.350 s | 266 ms | 4.192 s | 0 | 32 | 11 | 21 | 20 nodes / 54 edges |
| 50 / 144 | 3.459 s | 1.790 s | 1.670 s | 209 ms | 3.668 s | 0 | 97 | 50 | 47 | 50 nodes / 144 edges |
| 100 / 300 | 10.432 s | 3.243 s | 7.189 s | 2.198 s | 12.630 s | 0 | 215 | 118 | 97 | 100 nodes / 300 edges |

The worker computes inspection before replying, so the UI receives one scene/inspection pair. The “Worker compute” column is layout plus inspection and excludes worker startup, message serialization, and delivery overhead. The 20-node warm cosmetic edit reused cached geometry: layout took 31 ms, with no ELK call, inspection took 2 ms, and worker compute was 33 ms. A warm geometry edit changed one node label and reran ELK in 2.443 s (1.494 s ELK, 949 ms routing and other layout); inspection took 125 ms, for 2.568 s worker compute. Both retained all nodes and edges. The worker/client unit tests separately verify replacement cancellation, abort, timeout, worker disposal, worker reuse after success, matching inspection fingerprints, and preservation of the last-good scene and inspection on cancellation/error.

Production browser checks confirmed the default document composes with the hashed layout worker and nested ELK worker, both returning HTTP 200, with all six edges retained. The status/Inspector journey verifies the displayed issue count matches the inspection carried by the worker reply. These functional checks validate worker delivery and scene/inspection pairing; they do not establish a browser gesture latency budget. See [integration verification](verification/integration.md) for the final qualification status.

The transition cache and one-pass fallback scoring substantially reduced routing time at 50 and 100 nodes compared with the earlier unoptimized run (14.210 s to 3.459 s at 50 nodes; 80.438 s to 10.432 s at 100 nodes). Those earlier fixtures used classic nodes throughout; the final fixture adds one explicitly styled shape node, so these are close comparisons rather than exact same-scene deltas. The final cold 20-node case took 3.926 s versus 3.461 s previously; the warm cosmetic path is 31 ms. Routing quality remains the main limit: diagnostics reported no errors or dropped nodes/edges, but crossing and fallback warnings remain high at 50 and 100 nodes. Those warnings are retained and the fallback route marker is surfaced to inspection. These timings establish that this fixture completes within the 60-second client timeout up through 100 nodes / 300 edges; they do not establish a warning-free quality guarantee for dense diagrams. Grid mode bypasses ELK entirely, as covered by the focused layout test.

Raw measurements, diagnostic-code counts, and fixture parameters are in [`performance.json`](verification/performance.json).
